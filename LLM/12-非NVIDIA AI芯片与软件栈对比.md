## AI 芯片市场全景

### 1.1 市场格局

```
2024-2025 AI 训练/推理芯片市场:

  NVIDIA: ~80-90% (训练), ~70-80% (推理)
  Google TPU: ~5-10% (自用为主)
  AMD: ~3-5% (快速增长)
  Intel: ~1-2%
  华为昇腾: ~5-10% (中国市场)
  其他: ~1-2%

趋势:
  - NVIDIA 份额缓慢下降 (但仍绝对主导)
  - AMD 在推理市场快速增长
  - 云厂商自研芯片加速 (AWS Trainium, Google TPU)
  - 中国市场国产替代加速
```

## AMD：ROCm 生态

### 2.1 硬件架构

```
AMD CDNA3 架构 (MI300X):

  ┌─────────────────────────────────────────┐
  │            MI300X (APU 架构)             │
  │                                         │
  │  ┌─────────────────────────────────┐    │
  │  │  8 × Compute Chiplets (XCD)     │    │
  │  │  每个 XCD:                      │    │
  │  │  - 40 Compute Units             │    │
  │  │  - Matrix Core (类似 Tensor)    │    │
  │  │  - 4MB L2 Cache                 │    │
  │  └─────────────────────────────────┘    │
  │                                         │
  │  ┌─────────────────────────────────┐    │
  │  │  8 × HBM3 Stacks (192GB)        │    │
  │  │  带宽: 5.3 TB/s                 │    │
  │  └─────────────────────────────────┘    │
  │                                         │
  │  Infinity Fabric: 896 GB/s (GPU-GPU)    │
  │                                         │
  └─────────────────────────────────────────┘

关键差异 vs NVIDIA:
  - 显存更大 (192GB vs 80GB H100)
  - 显存带宽更高 (5.3 vs 3.35 TB/s)
  - 推理场景有显存优势
  - 但软件生态差距大
```

### 2.2 ROCm 软件栈

```
ROCm (Radeon Open Compute):

层次结构:
  ┌──────────────────────────────────────┐
  │  PyTorch / TensorFlow / JAX          │  ← 框架层
  ├──────────────────────────────────────┤
  │  MIOpen (cuDNN 等价)                 │  ← 库层
  │  rocBLAS (cuBLAS 等价)               │
  │  rocFFT, rocRAND, ...                │
  ├──────────────────────────────────────┤
  │  HIP (CUDA 等价)                     │  ← 运行时
  │  ROCclr (设备驱动接口)               │
  ├──────────────────────────────────────┤
  │  ROCk (Kernel 驱动)                  │  ← 驱动层
  └──────────────────────────────────────┘

HIP: CUDA 的 AMD 版本
  - 语法几乎相同 (hipMalloc vs cudaMalloc)
  - 可以自动转换 CUDA 代码 (hipify)
  - 但性能不一定等价
```

### 2.3 迁移挑战

```
从 CUDA 迁移到 ROCm 的挑战:

1. 算子覆盖:
   - 大部分常用算子已支持
   - 但部分高级特性缺失 (如 FlashAttention-3)
   - 自定义 CUDA kernel 需要重写

2. 性能差距:
   - 同等算力下，ROCm 性能通常低 10-30%
   - 原因: 编译器优化不如 NVCC
   - 部分 kernel 需要手动调优

3. 生态成熟度:
   - vLLM 已支持 ROCm
   - PyTorch 官方支持
   - 但第三方库支持参差不齐

4. 调试工具:
   - rocprof (nsys 等价)
   - 但功能不如 NVIDIA 工具链完善
```

## Google TPU：专用架构

### 3.1 硬件架构

```
TPU 架构特点:

  ┌─────────────────────────────────────────┐
  │              TPU v5p                     │
  │                                         │
  │  ┌─────────────────────────────────┐    │
  │  │  MXU (Matrix Multiply Unit)     │    │
  │  │  - Systolic Array 架构           │    │
  │  │  - 128×128 BF16 MAC per cycle   │    │
  │  │  - 专用矩阵乘法 (非通用 GPU)     │    │
  │  └─────────────────────────────────┘    │
  │                                         │
  │  ┌─────────────────────────────────┐    │
  │  │  VPU (Vector Processing Unit)   │    │
  │  │  - 通用向量运算                  │    │
  │  │  - 激活函数, LayerNorm, ...     │    │
  │  └─────────────────────────────────┘    │
  │                                         │
  │  ┌─────────────────────────────────┐    │
  │  │  ICI (Inter-Chip Interconnect)  │    │
  │  │  - 4.8 Tb/s 双向带宽            │    │
  │  │  - 3D Torus 拓扑                │    │
  │  └─────────────────────────────────┘    │
  │                                         │
  └─────────────────────────────────────────┘

关键差异:
  - 不是 GPU! 是专用 ASIC
  - 矩阵乘法是核心 (systolic array)
  - 灵活性低，但效率高
  - 编译器依赖极重
```

### 3.2 软件栈

```
TPU 软件栈:

  ┌──────────────────────────────────────┐
  │  JAX / TensorFlow / PyTorch (XLA)   │  ← 框架 (必须经过 XLA)
  ├──────────────────────────────────────┤
  │  XLA (Accelerated Linear Algebra)   │  ← 编译器 (核心!)
  │  - HLO (High-Level Optimizer)       │
  │  - LLO (Low-Level Optimizer)        │
  │  - 自动算子融合、内存分配            │
  ├──────────────────────────────────────┤
  │  TPU Runtime                        │  ← 运行时
  ├──────────────────────────────────────┤
  │  TPU Hardware                       │  ← 硬件
  └──────────────────────────────────────┘

XLA 编译器:
  - 必须将计算图编译为 TPU 指令
  - JIT (Just-In-Time) 编译
  - 静态 shape 优先 (动态 shape 性能差)
  - 编译时间可能很长 (首次运行)
```

### 3.3 使用限制

```
TPU 的限制:

1. 只能通过 Google Cloud 使用 (不对外销售芯片)
2. 必须使用 XLA 编译器 (不支持 eager mode)
3. 动态 shape 性能差 (需要 padding 到固定大小)
4. 调试困难 (编译后的代码难以分析)
5. 自定义算子困难 (需要写 HLO)

优势:
  - 大规模训练效率高 (Gemini 的训练硬件)
  - 成本可能更低 (Google Cloud 定价)
  - 与 GCP 生态集成好
```

## Intel Gaudi：网络优先

### 4.1 硬件架构

```
Gaudi 3 架构:

  ┌─────────────────────────────────────────┐
  │              Gaudi 3                     │
  │                                         │
  │  ┌─────────────────────────────────┐    │
  │  │  8 × MME (Matrix Multiply Eng.) │    │
  │  │  - 类似 Tensor Core             │    │
  │  └─────────────────────────────────┘    │
  │                                         │
  │  ┌─────────────────────────────────┐    │
  │  │  64 × TPC (Tensor Processor)    │    │
  │  │  - 通用 SIMD 引擎               │    │
  │  └─────────────────────────────────┘    │
  │                                         │
  │  ┌─────────────────────────────────┐    │
  │  │  24 × 200GbE RoCE (集成!)       │    │  ← 核心差异!
  │  │  无需外部 NIC                   │    │
  │  │  总网络带宽: 4.8 Tb/s           │    │
  │  └─────────────────────────────────┘    │
  │                                         │
  └─────────────────────────────────────────┘

关键差异:
  - 集成 RoCE: 不需要 ConnectX 网卡
  - 网络优先设计: 通信是核心能力
  - 但显存带宽相对低 (HBM2e vs HBM3)
```

### 4.2 软件栈

```
Habana 软件栈:

  ┌──────────────────────────────────────┐
  │  PyTorch (原生支持, 非 CUDA 后端)    │  ← 框架
  │  TensorFlow                          │
  ├──────────────────────────────────────┤
  │  Habana Bridge (图捕获 + 编译)       │  ← 编译器
  ├──────────────────────────────────────┤
  │  SynapseAI (运行时 + 库)             │  ← 运行时
  │  - TPC kernel library               │
  │  - 通信库 (集成 RoCE)               │
  ├──────────────────────────────────────┤
  │  Gaudi Hardware                      │  ← 硬件
  └──────────────────────────────────────┘

特点:
  - PyTorch 原生支持 (不需要改代码)
  - 自动图捕获和编译
  - 通信优化 (利用集成 RoCE)
```

## Apple Silicon：统一内存

### 5.1 架构特点

```
Apple Silicon (M 系列) 的 LLM 推理优势:

统一内存架构 (UMA):
  ┌─────────────────────────────────────────┐
  │              Apple Silicon               │
  │                                         │
  │  ┌─────────────────────────────────┐    │
  │  │  CPU + GPU + NPU                │    │
  │  │  共享统一内存                    │    │
  │  │  M2 Ultra: 192GB                │    │
  │  │  M3 Max: 128GB                  │    │
  │  │  带宽: 400-800 GB/s             │    │
  │  └─────────────────────────────────┘    │
  │                                         │
  └─────────────────────────────────────────┘

优势:
  - 大显存: 最高 192GB (超过 H100 80GB)
  - 零拷贝: CPU 和 GPU 共享内存
  - 低功耗: 适合本地推理
  - 成本: 整机价格 < 单张 H100

劣势:
  - 算力低: 远不如 H100
  - 训练: 不适合大规模训练
  - 生态: 软件栈不如 CUDA
```

### 5.2 推理框架

```
Apple Silicon 上的 LLM 推理:

MLX (Apple 官方):
  - 类似 NumPy/PyTorch 的 API
  - 统一内存模型
  - 支持 LoRA/QLoRA 微调
  - 性能优于 llama.cpp (Metal)

llama.cpp (Metal 后端):
  - 最成熟的方案
  - 支持 GGUF 量化格式
  - 社区活跃

CoreML:
  - Apple 原生推理框架
  - 需要模型转换
  - 功耗最优

性能参考 (M2 Ultra, Llama-3-70B Q4):
  - MLX: ~15 tokens/s
  - llama.cpp: ~12 tokens/s
  → 可用的本地推理速度
```

  │                                         │
  │  ┌─────────────────────────────────┐    │

### 6.2 软件栈

```
昇腾软件栈 (CANN):

  ┌──────────────────────────────────────┐
  │  MindSpore / PyTorch (Ascend 适配)   │  ← 框架
  ├──────────────────────────────────────┤
  │  CANN (Compute Architecture for NN)  │  ← 计算架构
  │  - AscendCL (编程接口)              │
  │  - 图编译 + 算子库                  │

挑战:
  - 软件生态差距大 (vs CUDA)
  - PyTorch 适配仍在完善
  - 第三方库支持有限
  - 文档和社区资源较少
```

## 新兴架构

### 7.1 Cerebras CS-3

```
Cerebras Wafer-Scale Engine:

  整个晶圆作为一个芯片!
  - 900,000 计算核心
  - 44GB 片上 SRAM
  - 极高带宽 (片上互联)
  - 不需要 HBM

特点:
  - 编程模型完全不同
  - 适合特定负载 (稀疏, 大规模)
  - 编译器驱动
  - 不适合通用 LLM 推理
```

### 7.2 Groq LPU

```
Groq LPU (Language Processing Unit):

  确定性数据流架构:
  - 纯 SRAM (无 HBM)
  - 编译器决定一切 (确定性调度)
  - 极低延迟 (~0.3ms per token)

特点:
  - 推理延迟极低
  - 但显存容量受限 (SRAM 小)
  - 适合小模型低延迟场景
  - 不适合大模型
```

## 软件栈适配难度评估

### 8.1 迁移难度

| 平台 | 迁移难度 | 说明 |
|------|---------|------|
| **NVIDIA CUDA** | ★☆☆☆☆ | 标准方案，无需迁移 |
| **AMD ROCm** | ★★☆☆☆ | HIP 自动转换，但需验证性能 |
| **Intel Gaudi** | ★★☆☆☆ | PyTorch 原生，但需适配通信 |
| **Google TPU** | ★★★★☆ | 必须用 XLA，动态 shape 困难 |
| **Apple Silicon** | ★★★☆☆ | 推理可用，训练受限 |
| **华为昇腾** | ★★★★☆ | 生态差距大，适配工作多 |
| **Cerebras/Groq** | ★★★★★ | 编程模型完全不同 |

### 8.2 选择建议

```
场景 → 推荐平台:

学术研究/开源项目:
  → NVIDIA (生态最好，资源最多)

大规模训练 (云):
  → NVIDIA (首选) 或 Google TPU (GCP)

推理部署 (成本敏感):
  → AMD MI300X (显存大) 或 Intel Gaudi 3

本地/边缘推理:
  → Apple Silicon (Mac) 或 NVIDIA (PC)

中国市场:
  → NVIDIA (如可获取) 或 华为昇腾

极致低延迟推理:
  → Groq LPU (小模型) 或 NVIDIA H100
```

---

> **关键原则**：
> 1. **NVIDIA 仍是首选**：生态成熟度无可替代
> 2. **AMD 是最有希望的挑战者**：硬件有竞争力，软件在快速追赶
> 3. **TPU 是云原生选择**：如果已经在 GCP，值得考虑
> 4. **软件栈比硬件更重要**：好的硬件 + 差的软件 = 无法使用
> 5. **关注开放标准**：UEC、OpenAI Triton 等可能改变格局
