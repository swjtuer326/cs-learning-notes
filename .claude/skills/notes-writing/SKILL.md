# 学习笔记写作规范

本仓库的笔记是给人(也给自己)读懂用的,不是操作手册。一篇好笔记把一个东西讲明白:**它解决什么问题、为什么这么设计、它换来了什么代价、和别的做法比怎么样**。init 序列、bring-up、配置这些步骤是为讲明白服务的,不是主角——读完读者是理解了这个东西,而不是记住了"怎么操作"。

规范只管两件事:**读得下去**(不刻板、不突兀)、**读完有收获**(理解了为什么、以及代价)。每条规则只解决其中一件,不解决这两件的不立规矩。语气是"读者会困惑于什么",不是"必须/禁止";遵守某条的字面形式若让本节变刻板,就换更自然的方式达到该条目标。

## 工程类 vs 科普类

两类都要讲明白,区别在底子:**工程/系统/源码类**(固件、驱动、芯片、协议、源码走读)讲的是具体系统,所以要点出它在系统里的位置、贴代码、和别的实现比;**科普/综述类**(概念入门、领域脉络)讲的是概念,所以多用小例子和类比,不必贴代码。混用以主导面定。

## 核心:别让读者读不下去

- **顺着一条线写,别平铺维度**。读者想跟着一个主线走("长程依赖怎么办 → O(N²) 怎么降 → KV 带宽怎么省"),不想在"时间/结构/效率"几个维度间来回跳。维度平铺是刻板感的头号来源。
- **章节之间别突然跳**。读者不该在章节开头犯迷糊"怎么突然讲这个"。过渡有交代就行,形式不限——一句话承接、一个引子、甚至上一节末尾已经埋好了就不必再写。**别每节都套同一句开头**(像"上一章建立了…一个自然的问题是…本章用…来回答")——这是刻板感的主要来源。
- **别为凑形式而写**。本质→小例子→公式→算一遍,不必每个概念都走全;代价不必每个机制单起一段;核心要点不必每节都收一个尾。哪处为凑形式写僵了,就换个更自然的方式把它说清楚。

## 核心:别让读者读完没收获

- **先让读者知道在干什么,再上公式/规范/代码**。形式化落地时读者跟得上,就算达标。
- **讲为什么,别只讲是什么**。引入一个机制要回答:它解决什么问题、不用它会怎样、为什么是这样做而不是那样。并把**代价**(它换来了什么)、**什么时候它反而不行**、**它把什么麻烦留给了别处**在某个地方说清楚——形式不限,能顺进去就行。只讲好处不讲代价是宣传,不是判断。
- **多方案对比要能用来选**。让读者看完答得出"什么情况下选谁",不是干列"A 有 X、B 有 Y"。科普类不是选型场景时,这条就弱化成"对照着讲帮人理解"。
- **复杂的公式用真实数字算一遍**,让读者能自己验;显然的、纯定义的公式就别硬算了。

## 底线(不展开)

- 非通识缩写第一次出现给全称;引用官方文档/规格标章节号;数值标来源、不确定就写 `> **待确认**`、别编。来源冲突按 规范 > 官方文档 > 论文 > 应用笔记 > 博客 > 推断 取更可信的。
- 排版上有客观对错的(Mermaid 图主题由构建兜底、代码块标语言、公式用 LaTeX、复用官方图要标来源),查 `references/conventions.md`,不必预先全读。

## 构建与 agent 工作流

本仓库的 md 用 `build_html.py` 构建成单文件 HTML——比纯 md 渲染更友好(侧边栏/搜索/代码行号/源码追踪),优先构建后查看。md 写法要和构建器对齐,详见 `references/conventions.md` 的"可构建性约定"。

写笔记的 md 按约定来,核心几条:
- **进 HTML 的文件**:只有 `README.md` + `NN-*.md`。正文用编号文件。
- **跨文档链接**:`[text](./NN-foo.md)` → 文档内跳转;`[text](./src/...)` → 源码。
- **源码引用**:优先用新语法 ``` ```c src="..." lines="..." anchor="名" ``` ```(构建时从源码拉取内联,防漂移);代码已手贴的旧笔记用 `/* 摘自 ... 第 X-Y 行 */` 注释(自动加徽章+行号)。函数名用 `` [`fn()`](#src-名) `` 链到代码块锚点,做轻量调用导航。
- **Mermaid**:写 ``` ```mermaid ``` ``` 块,主题构建兜底,不用写 `%%{init}%%`。

agent 写完一篇笔记后:
1. 先 `python3 build_html.py <专题目录> --check` 校验死链/缺图/坏 mermaid/源码引用问题,有 error 退出码非 0,据此修。
2. 通过后 `python3 build_html.py <专题目录>` 构建 HTML 查看效果。
3. 要看每篇渲染了多少图/代码块/源码引用,加 `--check --json`,输出机器可读。

## 写完通读一遍,只问自己两件事

- 顺着读下来通吗?有没有套同一句开头、硬凑的段落、凑数的小结,让文章变僵了?
- 读完懂这个东西了吗(它解决什么、为什么这么做、代价是什么、和别的比怎样)?还是只记住了一堆"是什么"?
